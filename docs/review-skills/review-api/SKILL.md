# review-api

1. Сопоставь изменённый запрос/ответ с docs/api.md, docs/grpc-api.md, openapi/proto в contracts и проверяемым кодом. Для вычислений используй docs/calc.md. Если источник отсутствует, назови его и ограничь вывод доступными данными.
2. Проверь смысл, единицу, знак, валюту, календарный пояс и границы дат, отсутствие/null, error/retry metadata. Серверное разрешение повторить исходный запрос не равно новой попытке действия пользователя.
3. Для новой формы проверь старого и нового потребителя: неизвестные поля/открытые коды, версии блоков, зарезервированные protobuf номера, порядок rollout. Не предлагай закрытый enum для растущего множества или новую версию без необходимого breaking change.
4. Проверь auth/caller model, tenant binding, лимиты и идемпотентность операции. Фикстура схемы не доказывает поведение сервиса; назови тест потребителя для достижимой ошибки и неизвестного значения.
5. Зафиксируй проверенную пару источник → потребитель и результат. Доступ к contracts не подразумевает доступ к Confluence; не заявляй чтение недоступного источника.

Результат — проверяемые наблюдения в рамках Code Review Rules. Сам навык не разрешает внешние действия.
