# Расчёт метрик MVP (FIN-355)

Источник правил — `fin-assist/contracts/docs/calc.md` на main (проверен commit `1683646`).
`internal/accounting` — начальный единый каталог определений: пороги истории для импорта и метрик,
параметры пар/возвратов, регулярности, заметных и мелких трат, словоформы комиссий.
`accounting.Classify` одинаково определяет RUB-суммы итога импорта и метрик: возврат уменьшает расход
цели, пары и одиночные переводы себе исключены, режим `without` дополнительно исключает «Переводы».
Другие валюты не складываются с RUB.

`internal/calculating.Build` — детерминированный расчёт одного месяца/квартала/года из coherent
`importing.Snapshot`, момента расчёта и хранилища непрозрачных ссылок. В результате всегда **два**
полных снимка одного периода (`with`/`without`) и глобальное состояние пользователя.
Каждая метрика имеет статус, числовое значение/типизированные детали, условие открытия, историческую
базу и готовые фильтры. Все межмесячные значения рассчитываются из операций; чужие сохранённые снимки
не читаются. Денежные суммы — int64; переполнение возвращает безопасную ошибку. Промежуточные
умножения/деления — точная целочисленная арифметика; средние по периодам и экстраполяция квартала/года
округляются `floor(x + 0.5)`, включая отрицательные значения.

`App.Calculations.Calculate(ctx, user, kind, at)` — собранный внутренний сценарий для будущего worker.
Он получает tombstone guard, блокирует существующую строку пользователя и читает факты в одной
транзакции. `regular_payment` и `merchant` получают устойчивые UUID из существующей схемы; отметка
«Не подписка» сохраняется при повторном расчёте. Описание операции не кодируется в UUID/selection.
`at` выбирает период по локальной дате профиля; worker должен строить начало даты очереди в этом поясе,
а не трактовать PostgreSQL `date` как UTC-момент.
Новый RPC, worker, триггеры, `calc_version`, outbox/delivery и backfill здесь не вводятся — это FIN-357/FIN-6.
`internal/adapter/metricswire.Encode` переводит результат в текущие типизированные `UserDataState` и
`PeriodSnapshot` из contracts v0.5.0; текст `lock.text` дополняет analytics. При передаче worker сохраняет
оба режима вместе, назначает версию и отвечает за tombstone/outbox на границе записи.

## Календарь и отсутствие данных

Покрытие берётся из завершённых загрузок через тот же `importing.CompletedPeriods`, что и история:
при отсутствии границ — сохранённый итог или source membership. Периоды включают пустые выписки.
Даты считаются в IANA-поясе профиля; неизвестный пояс в чистом расчёте — `Europe/Moscow`.
Смежные дни объединяются; `gaps` сохраняются целиком, даже если выходят за выбранный период.
Нет покрытых дней — отсутствующее значение, покрытые дни без подходящих операций — ноль.
`stale_after` — начало 15-го календарного дня после последнего покрытого дня, с учётом DST.
У старого периода и устаревших данных прогноз отсутствует; актуальный прогноз до 10-го числа закрыт.
Готовность полного месяца требует, чтобы его последний день был раньше сегодняшнего.

## Общие выборки для последующих API (FIN-356/FIN-358)

`calculating.FinancialRow` и `Match` — общая классификация и проверка готового фильтра; текстовый `q`
для финансовых переходов не используется. Возврат выбирается как расход категории-цели. Период всегда
задают только `from/to`, `selection` не содержит дат.

- `s_bank_fees` и `s_uncategorized` — встроенные правила.
- `s_regular_<UUID>` — точное описание из пользовательской `regular_payment`.
- `s_merchant_<UUID>` — точное описание из пользовательской `merchant`.
- `s_regular_all` — описания распознанных и не исключённых платежей для выбранного периода; переход
  отбирает списания в выбранном периоде, а не в окне распознавания.
- `s_small_category_<category_id>` — категория без операций продавцов, которые уже вошли в мелкие
  частые группы в том же полном месяце; эти группы сначала вычисляются тем же правилом `small`.

Вызывающий разрешает UUID **только с user_id**, а в `Match` передаёт точный ключ и множество описаний
распознанных платежей (для `s_regular_all`) либо продавцов мелких групп (для категории).
Недействительная ссылка должна стать существующей контрактной `SELECTION_NOT_FOUND` в будущих
адаптерах поиска; `Match` неизвестный токен не расширяет до всех операций.

## Проверки

Unit покрывает формулы, общую классификацию/фильтры, ошибки, календарь/DST и денежные границы.
Integration проходит импорт fixture-OFX → реальный PostgreSQL18 → оба снимка всех типов периодов,
повторный расчёт/UUID, «Не подписка», tenant scope и purge. API-набор импортирует те же файлы через
настоящие `UploadStatement/WatchUpload`, считает через ту же собранную внутреннюю точку и удаляет
пользователя публичным системным `PurgeUserData`. Новый публичный расчётный RPC не придумывается.
Сквозная доставка до analytics остаётся FIN-357/FIN-362.

`internal/app/testdata/calculation-reference.json` — числовая проекция неизменённых `fixtures/calc/expected`
из contracts `1683646`: плитки и категории десяти month/quarter/year ответов в двух режимах.
Текущий `calc.md` остаётся главным источником при расхождениях с референсом.
